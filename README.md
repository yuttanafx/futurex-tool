# AI FutureX Tool (P1)
1. สร้างโปรเจกต์ที่ supabase.com แล้วรัน `supabase/migrations/001_init.sql` ใน SQL Editor
2. (ทดสอบเร็ว) Auth → Providers → Email → ปิด "Confirm email"
3. `cp .env.example .env.local` ใส่ URL + anon key แล้ว `npm i && npm run dev`
4. Deploy: push ขึ้น GitHub → Vercel → Import → ใส่ env 2 ตัวเดิม → Deploy
5. P2/P3: รัน `002_commerce.sql` และ `003_ai.sql` ตามลำดับ
6. P3: ตั้ง `SUPABASE_SERVICE_ROLE_KEY`, `OPENAI_API_KEY` (และ `OPENAI_MODEL` ถ้าต้องการ) ใน Vercel → Settings → Environment Variables ห้ามใส่ NEXT_PUBLIC_ นำหน้า
7. P4: รัน `004_integrations.sql` แล้ว Deploy ใหม่ (ไม่มี env เพิ่ม) · LINE: ตั้ง Webhook URL ตามหน้า /app/integrations
8. 005_p3_leftovers.sql แล้ว Deploy ใหม่ · ตั้ง NEXT_PUBLIC_SITE_URL เป็นโดเมนจริง (ใช้กับ sitemap)
9. P5: รัน 006_cross_tenant_hardening.sql แล้วทดสอบสิทธิ์ด้วย `npm run test:rls` (ใช้โปรเจกต์ Supabase ทดสอบ + .env.local ที่มี key ครบ 3 ตัว)
10. 007_cart_referrals.sql → ตะกร้าหลายสินค้า + ลิงก์แนะนำ /r/รหัส (ดูที่ /app/referrals)
11. 008_product_details.sql → เพิ่มรายละเอียด/รูปสินค้า และหน้าสินค้า /s/ร้าน/products/id
12. พื้นหลังอนิเมชันการตลาด (`components/MarketingBackground.tsx`) + สลับกลางวัน/กลางคืน + สลับภาษา ไทย/EN/中文 (`components/Prefs.tsx`, `lib/i18n.ts`) · เก็บค่าที่เลือกไว้ในคุกกี้ `ui_theme` / `ui_lang` · ข้อความใหม่ให้ใช้ `<T th="…" en="…" zh="…" />`
13. 009_storefront_checkout.sql → หน้าร้านแบบอีคอมเมิร์ซ: รูปสินค้าหลายรูป (อัปโหลดขึ้น Supabase Storage bucket `shop-media`), ราคาก่อนลด, สต็อก, หมวดหมู่, ตะกร้าสินค้า, หน้าชำระเงิน `/s/ร้าน/checkout`, หน้าติดตามออเดอร์ `/s/ร้าน/order/โทเคน` · ตั้งพร้อมเพย์/บัญชีธนาคาร/ค่าส่งที่ /app/settings · ต้องรัน `npm i` ใหม่ (เพิ่ม `qrcode`) · ลูกค้าแนบสลิปไป bucket `slips` แล้วเจ้าของร้านกดยืนยัน "ชำระแล้ว" ที่ /app/orders (ยังไม่ได้ต่อ payment gateway บัตรเครดิต)
14. 010_platform_admin.sql → แอดมินดูแลทั้งแพลตฟอร์มที่ /admin (ยอดรวม รายร้าน ระงับร้าน เปลี่ยนแพ็กเกจ) · ตั้งตัวเองเป็นแอดมินด้วย SQL ท้ายไฟล์ 010 (insert into platform_admins ...)
15. 011_starter_shop.sql → ร้านใหม่ทุกร้านเริ่มด้วยหน้าร้านพื้นฐาน (แบนเนอร์ `public/starter/banner.jpg`, สโลแกน, เกี่ยวกับร้าน) และสินค้าตัวอย่าง 7 รายการ (รหัส `SAMPLE-01…07` รูปอยู่ใน `public/starter/`) ทุกอย่างแก้/ลบได้ที่ /app/products และ /app/settings (ช่อง “เกี่ยวกับร้าน” ใหม่) · แต่ละบัญชีเห็น/แก้ได้เฉพาะร้านตัวเอง · ร้านเดิมที่ยังไม่มีสินค้ากดปุ่ม “โหลดสินค้าตัวอย่าง” ที่หน้าสินค้า หรือรันบรรทัด `select seed_starter_shop('UUID ร้าน', true)` ท้ายไฟล์ 011 เพื่อใส่หน้าร้านพื้นฐานให้ร้านเดิม
16. `npm run check:tenant` → ตรวจว่าโค้ดแดชบอร์ดกรอง tenant ครบ (ตาราง products / sales_pages / tenants เปิดอ่านสาธารณะเพื่อหน้าร้าน ถ้าลืมกรอง สมาชิกจะเห็นข้อมูลร้านอื่น) · ควรรันทุกครั้งก่อน deploy คู่กับ `npm run test:rls`
17. 012_futurex_samples.sql → เปลี่ยนสินค้าตัวอย่างเป็นสินค้า FutureX (YANEA, SANEA, PROM PORM Candy Detox, MATCHA/PSP/CELONYA, Happy Grain) จาก future-x.biz/th · ยังเป็น `SAMPLE-01…07` เหมือนเดิม · มีผลกับร้านที่สมัครใหม่ ร้านเดิมดูคำสั่งที่คอมเมนต์ท้ายไฟล์ · ราคา YANEA/SANEA เป็นราคาจากเว็บ ส่วนที่เหลือเป็นราคาตัวอย่าง
18. 013_ai_keys.sql → แต่ละร้านใส่ API key ของ Claude / GPT / Gemini ของตัวเองที่ /app/ai-keys (ลิงก์อยู่ใน /app/settings และเมนู “ตั้งค่า API ของ AI”) · key เก็บเข้ารหัส AES-256-GCM แยกตามร้าน ไม่แสดงกลับ ใช้กับคลังคอนเทนต์ แชทหน้าร้าน และผู้ช่วยไลฟ์ · **ต้องตั้ง `AI_KEY_SECRET` ใน Vercel** (สตริงสุ่มยาว ≥16 ตัว เช่น `openssl rand -hex 32` ห้ามใส่ NEXT_PUBLIC_ และห้ามเปลี่ยนภายหลัง ไม่งั้น key ที่ร้านบันทึกไว้จะถอดรหัสไม่ได้) · ร้านที่ใช้ key ตัวเองไม่นับเข้าโควตา AI ของแพ็กเกจ (มีเพดานฉุกเฉิน 10 เท่าของโควตา/วัน กันแชทสาธารณะถูกยิงรัว) · ค่าเริ่มต้นไม่ใช้ `OPENAI_API_KEY` กลางอีกแล้ว ถ้าอยากให้ร้านที่ไม่มี key ใช้ key กลางเป็นตัวสำรอง ให้ตั้ง `AI_PLATFORM_FALLBACK=1` · ชื่อโมเดลเริ่มต้น: gemini-3.8-flash / claude-sonnet-5-5 / gpt-6-luna (ร้านแก้เองได้ในหน้าตั้งค่า)
19. 014_billing_facebook.sql → **ระบบเก็บค่าบริการ + เชื่อมเพจ Facebook** (รันต่อจาก 013 ต้องมี 010 แล้ว)
    - **ค่าบริการ (แอดมิน)** ที่ `/admin/billing`: ตั้งค่าเว็บไซต์รายเดือน · ค่ายูสเซอร์รายเดือน (คิดเฉพาะยูสเซอร์ที่เกินโควตาที่ตั้งไว้) · ราคาแพ็กเกจ Starter/Pro/Business · ติ๊ก ⭐ ชั้นแนะนำ · ทุกรายการตั้งราคาเป็น **บาท / PV / วอลเล็ต** ได้พร้อมกัน และติ๊กว่าให้ร้านจ่ายด้วยแบบไหนได้ (ร้านจ่ายได้เฉพาะวิธีที่เปิดไว้ครบทุกรายการที่ต้องจ่าย) · ตั้งพร้อมเพย์/บัญชีธนาคารรับเงินของแพลตฟอร์ม · อนุมัติ/ไม่อนุมัติสลิป · เพิ่ม/ลดวอลเล็ต, PV และวันใช้งานของแต่ละร้านที่ `/admin/shops/ไอดี`
    - **ฝั่งร้าน** ที่ `/app/billing`: ดูวันครบกำหนด/ยอดวอลเล็ต/PV · เลือกแพ็กเกจ จำนวนเดือน (1/3/6/12) และวิธีจ่าย · วอลเล็ต/PV หักทันทีและต่ออายุ · บาท = ใบแจ้งหนี้ + QR พร้อมเพย์ + แนบสลิป รอแอดมินอนุมัติ · เติมวอลเล็ตด้วยการโอน · มีแถบเตือนก่อนครบกำหนด 7 วัน · หน้า `/pricing` ดึงราคาจริงและแสดงป้าย ⭐ แนะนำ
    - ยอดเงินทุกอย่างคำนวณและหักใน DB (ล็อกแถว กันยอดติดลบ มีสมุดบัญชี `billing_ledger`) · ตารางเงินเขียนผ่านฟังก์ชันเท่านั้น · เพิ่ม trigger กันสมาชิกร้านแก้ `plan_id`/`status` ของ `tenants` ตัวเองผ่าน API (เดิม policy เปิดทุกคอลัมน์)
    - PV ไม่ได้ผูกกับระบบสมาชิก FutureX อัตโนมัติ: แอดมินเติม/ลดให้เองที่หน้าร้านนั้น (ถ้าต้องดึงจาก API สมาชิกให้เรียก `admin_adjust_balance`)
    - **เพจ Facebook** ที่เมนู “เซลเพจ” (`/app/pages`): ปุ่ม “เชื่อมเพจ Facebook” (OAuth) หรือวาง Page Access Token เอง → เก็บเพจไว้ในร้าน (token เข้ารหัสด้วย `AI_KEY_SECRET`) → โพสต์ลงเพจจากหน้าเซลเพจหรือปุ่ม “โพสต์ลงเพจ” ในคลังคอนเทนต์ → เปิด “AI ตอบแชท” ต่อเพจ ข้อความ Messenger เข้า Inbox, AI ตอบด้วย key ของร้าน (ลูกค้าพิมพ์ขอคุยกับเจ้าหน้าที่ → ส่งต่อคน) · เจ้าหน้าที่ตอบกลับ Messenger ได้จาก Inbox
    - env ที่ต้องตั้งเพิ่ม (Vercel): `AI_KEY_SECRET` (มีอยู่แล้วจาก 013), `NEXT_PUBLIC_SITE_URL` (โดเมนจริง ใช้เป็น redirect), `FB_APP_ID`, `FB_APP_SECRET`, `FB_VERIFY_TOKEN` (สตริงสุ่มอะไรก็ได้), `FB_GRAPH_VERSION` (ไม่ใส่ = v23.0)
    - ตั้งค่าที่ Meta for Developers (ทำครั้งเดียว): Facebook Login → Valid OAuth Redirect URI = `https://โดเมน/api/v1/facebook/callback` · Webhooks → Page → Callback URL = `https://โดเมน/api/v1/webhooks/facebook` + Verify token = `FB_VERIFY_TOKEN` + ติ๊ก `messages` · สิทธิ์ที่ขอ: `pages_show_list, pages_manage_posts, pages_read_engagement, pages_manage_metadata, pages_messaging` (ใช้กับเพจของคนอื่นต้องผ่าน App Review/Business Verification ของ Meta ก่อน ระหว่างนั้นใช้ได้กับเพจที่ผู้ดูแลแอปเป็นแอดมิน) · Messenger ตอบลูกค้าได้ภายใน 24 ชม. หลังลูกค้าทักล่าสุด
